## Top 5 Things to Fix

1. **No 404 page** — invalid URLs serve the homepage with 200 status. Terrible for SEO and user trust. [critical]
2. **No sitemap.xml** — `/sitemap.xml` returns the homepage HTML. Search engines cannot index the site properly. [high]
3. **No OG/Twitter meta tags on any page** — links shared on LinkedIn, WhatsApp, X will look broken with no preview. For a HNWI audience this is unacceptable. [high]
4. **No canonical URLs** — duplicate content risk across trailing-slash and non-trailing-slash versions. [high]
5. **Contact form uses FormSubmit.co** — a free third-party service with no SLA. Cloudflare email obfuscation may interfere with the `mailto:` action. No CSRF protection, no rate limiting. [high]

## All Issues

### Critical

**ISSUE-001: No custom 404 page** [functional]
- `/nonexistent-page` returns HTTP 200 with the full homepage content
- Users who mistype a URL see no indication they're on the wrong page
- Search engines will index garbage URLs as duplicates of the homepage
- Fix: Create `src/pages/404.astro` with a proper error page
- Difficulty: trivial

### High

**ISSUE-002: sitemap.xml returns homepage HTML** [seo]
- `curl https://new.jerseytrust.ae/sitemap.xml` returns the homepage, not XML
- Astro has a `@astrojs/sitemap` integration, it needs to be installed
- Fix: `npx astro add sitemap`, configure in `astro.config.mjs` with `site: 'https://jerseytrust.ae'`
- Difficulty: trivial

**ISSUE-003: No Open Graph or Twitter Card meta tags** [seo]
- None of the 6 pages have `og:title`, `og:description`, `og:image`, `twitter:card` tags
- Sharing any page on LinkedIn, WhatsApp, X, or Slack will show no preview
- For a business targeting HNWIs who are shared referral links, this is a significant gap
- Fix: Add OG/Twitter meta tags to `Layout.astro`
- Difficulty: easy

**ISSUE-004: No canonical URLs** [seo]
- No `<link rel="canonical">` on any page
- All pages have both `/about` (308 redirect) and `/about/` (200) variants
- Search engines may index both, splitting page authority
- Fix: Add canonical tags in `Layout.astro`, install sitemap integration
- Difficulty: easy

**ISSUE-005: Contact form security concerns** [security]
- Form action is `https://formsubmit.co/info@jerseytrust.ae` — a free third-party
- No CSRF token, relies on honeypot field only
- No client-side validation beyond `required` attributes
- Cloudflare's email obfuscation script is loaded (`email-decode.min.js`) which may mangle the `mailto:` in the form action
- No form submission confirmation/thank-you page
- Fix: Consider Cloudflare Workers form handler or at minimum verify FormSubmit.co works with CF email obfuscation
- Difficulty: moderate

**ISSUE-006: Cloudflare email obfuscation active** [functional]
- `email-decode.min.js` is loaded by Cloudflare, may obfuscate email addresses in the HTML
- Could break the FormSubmit.co form action and visible `mailto:` links
- Fix: Test form submission end-to-end. If broken, disable email obfuscation in Cloudflare dashboard or use a Workers-based form handler
- Difficulty: easy

### Medium

**ISSUE-007: No active navigation state** [ux]
- Current page is not highlighted in the nav bar
- User cannot tell which page they're on from the navigation
- Fix: Compare `Astro.url.pathname` against nav item hrefs, add active class
- Difficulty: easy

**ISSUE-008: Footer logo uses `brightness-0 invert` filter** [visual]
- The red/gold logo is forced to white via CSS filter, losing brand identity
- A white variant of the logo SVG would be cleaner
- Fix: Create a white logo variant or use the logo without the filter if it works on dark background
- Difficulty: easy

**ISSUE-009: "What Sets Us Apart" red accent bars don't render properly** [visual]
- The `w-1 h-full` divs meant to be vertical accent bars have no visible height
- `h-full` on a flex item without a defined parent height collapses to 0
- Fix: Use `self-stretch` on the accent div or set a min-height
- Difficulty: trivial

**ISSUE-010: Mobile hamburger menu has no close animation** [ux]
- Menu toggles with a hard show/hide (class `hidden`)
- No visual transition, icon doesn't change to X when open
- Fix: Add transition classes and toggle hamburger/close icon
- Difficulty: easy

**ISSUE-011: No `lang` attribute consistency** [accessibility]
- Pages use `<html lang="en">` but content is UK English
- Should be `<html lang="en-GB">` for screen readers and translation tools
- Difficulty: trivial

**ISSUE-012: Form labels not using `<label>` elements properly** [accessibility]
- Contact form labels are `<label>` but the snapshot shows them as generic `<generic>` elements
- The `for`/`id` association appears to work but should be verified
- Difficulty: trivial

### Low

**ISSUE-013: No favicon.svg (serves default)** [visual]
- `/favicon.svg` returns 200 but is likely the default Astro favicon
- Should be the JT shield mark
- Difficulty: trivial

**ISSUE-014: Logo PNG is 153KB** [performance]
- `jersey-trust-logo.png` is 153KB, loaded on every page (twice: header + footer)
- Should be optimised (WebP/AVIF) and sized appropriately. Header only needs ~56px height
- Fix: Use Astro `<Image>` component or manually create optimised variants
- Difficulty: easy

**ISSUE-015: Google Fonts loaded as render-blocking** [performance]
- Two font families (Inter + Playfair Display) loaded via Google Fonts CSS
- This is a render-blocking request that delays first paint
- Fix: Use `font-display: swap` (already set by Google), consider self-hosting fonts
- Difficulty: moderate

**ISSUE-016: No `aria-current="page"` on active nav link** [accessibility]
- Screen readers cannot identify the current page in navigation
- Fix: Add `aria-current="page"` to the active nav item
- Difficulty: trivial

**ISSUE-017: Services page has inconsistent content depth** [content]
- RAK Foundations card has a "Learn More" link but the other 5 service cards don't have individual pages
- All non-RAK services link to `/services` (the same page they're on)
- Fix: Either create individual service pages or make the cards non-linking with anchor IDs
- Difficulty: moderate
